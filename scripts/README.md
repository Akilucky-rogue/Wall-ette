# Dev Scripts

One-off development and debugging tools. None of these ship with the app.

| Script | Purpose |
|---|---|
| `verify-statements.mjs` | Regression check (any bank the app reads): runs the real PDF and Excel parsers over every statement in a folder and checks totals against the bank, to the paisa |
| `check-dates.mjs` | Regression check: transaction dates stay on the day picked, in several time zones (audit H4) |
| `check-contrast.mjs` | Regression check: main, second and secondary text reach 4.5:1 on the page, cards and pale cards in every theme (utils/theme.ts) |
| `check-spend.mjs` | Regression check: payee rules and defaults decide what counts as spending, income or money moved (audit H3, M8, M9); from 1.5.8, "To review" and rule categories, the review's guesses, reversals paired by bank reference, redemptions, and payee names (bank codes, UPI IDs, gateways, UPI Lite); from 1.5.9, Flow's money diagram names each payee and category once |
| `check-app-updates.mjs` | Regression check: when the app offers, requires or skips a Google Play update, when "What's new" appears, and that the release notes match `android/app/build.gradle` |
| `check-duplicates.mjs` | Regression check: bank references, transaction keys, stable import ids and duplicate matching on made-up narrations (audit L1–L3). Given a statements folder, also replays the audit's re-import tests on real statements, before and after, printing counts only |
| `check-cloud-saves.mjs` | Regression check: refused cloud writes are kept for the "didn't save" banner, sent again by Try again, and dropped on Dismiss or a new sign-in (audit M4) |
| `check-crash-reports.mjs` | Regression check: crash reports mask personal data, parse stack traces, report each error once (20 a session at most), stop when turned off, and send nothing on the web |
| `check-bank-statements.mjs` | Regression check: made-up statements in each bank's layout (Kotak, Saraswat, Union Bank and SBI PDFs; HDFC and IDFC FIRST Excel) read to the right rows, directions and totals; amounts, bank detection, payees, references and categories for each narration style; a PDF with no text says what to do |
| `check-password-reset.mjs` | Regression check: Forgot Password's results and messages for each Firebase answer, and typo suggestions for mail domains |
| `check-pulse.mjs` | Regression check: Pulse's analysis (services/pulseAnalysis.ts) on a hand-worked wallet (figures, projection, same-day comparison, usual, split, insights, a wallet whose entries stop early, a first month that starts late) and invariants on 300 random wallets: categories, the split, the days and the month's column add up to the month's spending; shares add up to 100; payments still to review stop the month comparison |
| `check-report.mjs` | Regression check: Data Studio's statement and spreadsheet (services/statementReport.ts) add up and match Pulse, escape payee text, and write formula-like CSV cells as text |
| `check-restore.mjs` | Regression check: Data Studio's full backup read back (services/backup.ts): every entry and setting comes back as saved, to the paisa; a restore adds only what the wallet lacks; version 1 files still restore; files that aren't backups, newer versions and huge files are refused; malformed rows (ids that would break a Firestore path, bad amounts, types, days, half-typed currencies, repeated ids) are counted and left out; only an entry's own fields come back; 20,000 entries in well under two seconds |
| `check-import.mjs` | Regression check, end to end: runs Import's whole path (the readers, `toTransactions`, duplicates, the balance check and the wallet merge) on every statement in a folder (default `private/statements`) and on made-up cases: no row lost, debits and credits to the paisa, balance equals the bank's closing, with the very same entries, in every import order (all orders for up to five statements per account), re-imports add nothing, a gap bridged and then filled leaves no adjustment, a wallet holding other accounts and cash gets a note rather than "off", and rows left out or ticked twice are named. Prints counts only |
| `check-entry.mjs` | Regression check: New entry's keypad and the entry it saves (`entryFromForm`), amounts typed in any currency saved in rupees to the paisa and read back as typed, 2,000 typed entries summed to the paisa |
| `check-currency.mjs` | Regression check: currency formatting (Indian grouping for rupees, each currency's decimals), the currency picker's list and quick amounts |
| `check-notifications.mjs` | Regression check: the bell's notifications from made-up wallets (failed unlocks, budgets, the daily limit, entries imported twice, double charges, bank charges, price rises, bills due, the import reminder, the savings goal), and how seen and dismissed ones are kept |
| `check-accounts.mjs` | Regression check: Bank accounts (services/accounts.ts `accountSummaries`): each account's balance is its opening balance plus its own entries, and the accounts and other entries add up to the wallet's balance to the paisa on 300 random wallets; rows imported before 1.5.9 count in the account that took over the opening balance from then; every entry is in one place, as Vault's account filter shows them |
| `check-payment-alerts.mjs` | Regression check: payments from notifications and shared text (services/paymentAlerts.ts): only the listed apps are read (never a messaging app), and the Android reader's list and the manifest's match; payment apps' phrases and bank apps' alerts give the right direction, amount to the paisa, day, payee, reference and rail, and which are sure; cashback waits for a tap; chat, OTPs, failed and pending payments, requests, bills due, mandates, offers and balance alerts give nothing; only last four digits; entries read like statement narrations so a statement finds them; the same notification gives the same id; 10,000 read in well under a second |
| `check-captured.mjs` | Regression check: what Wall-ette adds from apps (services/captured.ts): sure ones added, doubtful ones and "Ask me first" asked about, nothing counted twice (the same notification, an app posting it again, two apps for one payment, a typed entry, a statement row); a statement's rows take the place of the entries they stand for (by reference, or amount, a day either side and the payee's words) keeping category and note, with the balance and the balance check right |
| `qa-google-services.mjs` | Makes `android/app/src/qa/google-services.json` for the test build (`com.wallette.app.test`) from the app's own; both gitignored |
| `check-months.mjs` | Regression check: entries stored by month (services/months.ts): every entry in its own month's document, the same way every time, a month too big for one document spilling into parts; saves, moves to another month and take-outs; an id in two documents read once; the old documents' REST format read to the paisa. With the Firestore emulator (`npx firebase emulators:exec --only firestore --project demo-wallette "node scripts/check-months.mjs"`): the rules, entries replaced whole, two devices in one month, and the move (older versions refused from 'moving' on, every entry moved to the paisa, the old documents deleted, a second run changing nothing) |
| `check-back-button.mjs` | Regression check: Android's back button closes the newest open sheet, dialog or panel first, one per press, before it moves between screens; a panel closed another way takes no press; one that's busy saving stays open and still takes the press (utils/backStack.ts) |
| `test-parser.mjs`, `test-summary.mjs` | Exercise the IDFC statement parsers against local statement files |
| `analyze-excel.mjs`, `analyze-excel-detailed.mjs` | Inspect raw Excel statement structure while developing the parser |
| `analyze-last-transactions.mjs`, `compare-dashboard-vs-statement.mjs` | Reconciliation checks between parsed data and statement totals |
| `brand-icons.mjs` | Wall·ette's icon, drawn once as SVG (traced from the brand kit's approved icon) and rendered at every size it ships in: Android's adaptive layers, themed and legacy icons and the launch icon, the Play and App Store icons, the iOS icon and launch image, and the web app's and website's favicons. Needs `rsvg-convert` (librsvg) and ImageMagick's `convert` |

Statement files used by these scripts live in `../private/statements/` (gitignored — personal data).
